# GitHub AppHub Icon 候选方案

本轮 icon 目标：

- 更符合 macOS 客户端图标标准。
- 更清爽、更明亮，减少复杂小块和暗色大面积背景。
- 不使用 GitHub Logo、Octocat、文字、字母或容易混淆的商标元素。
- 保持“发现开源 app + 下载”的产品含义。

## 方案 1：Package Card

文件：

```text
Assets/IconOptions/icon-option-1-package-card.png
```

特点：

- 含义最直接：应用窗口 + 下载托盘。
- 比上一版更亮，元素也少很多。
- 适合强调“找 app、下载 app”的用户心智。

注意：

- 顶部窗口仍有 4 个小应用块，信息量中等。

## 方案 2：Compass Download

文件：

```text
Assets/IconOptions/icon-option-2-compass-download.png
```

特点：

- 最清爽、最亮、最容易在 Dock 里识别。
- 指南针表达“发现”，下载按钮表达“下载”。
- 细节少，小尺寸表现预计最好。

注意：

- 更像“浏览/发现工具”，对“开源 app 仓库”的表达较抽象。

## 方案 3：Repository Box

文件：

```text
Assets/IconOptions/icon-option-3-repository-box.png
```

特点：

- 最贴近“应用仓库 / app catalog”的概念。
- 三个 app tile 从盒子里浮出，表达收录和下载。
- 比上一版更简洁、更浅色。

注意：

- 盒子体积较大，小尺寸下下载符号可能不如方案 2 清晰。

## 方案 4：App Shelf

文件：

```text
Assets/IconOptions/icon-option-4-app-shelf.png
```

特点：

- 开源分支符号 + 下载托盘，产品含义完整。
- 留白多，整体现代、轻量。
- 适合强调“开源软件浏览器”。

注意：

- 分支符号可能让部分用户联想到 Git 客户端，而不是 app catalog。

## 建议

首选：方案 3。

理由：它最贴合“收录、展示、下载 GitHub 上各种 app”的产品定位，同时比上一版更明亮简洁。

备选：方案 2。

理由：如果你更看重 Dock 小尺寸识别和清爽感，方案 2 最稳。
